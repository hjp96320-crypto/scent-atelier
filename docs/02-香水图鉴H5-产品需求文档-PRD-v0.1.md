## 1. 已确认的方向与本版决策

### 1.1 用户已确认

1. 产品包括主流品牌香水图鉴、化学知识与量化解释、DIY 配比探索、每日用香记录，以及结合天气/日程的推荐。
2. DIY 从数十款预设的完整基础香水（base）中选择，自定义混合比例。base 是已有复合香气，不是单个分子，也不是只有“木质”“花香”名称的抽象旋钮。
3. 平台为手机和电脑均方便使用的 H5 网页。
4. 世界品牌地图只是参考灵感，不需要复制其复杂度。
5. 正式图鉴使用真实品牌、真实产品图片和可追溯信息，优先接入现成数据库。DIY 以 3–4 款为主要体验，遵循对应材料和商家的真实步骤，不绑定日本案例。

### 1.2 为推进首版采用的方案建议

以下属于产品方案，并非用户逐项确认的要求，可在原型阶段调整：

- 中文优先；四个一级入口为“今日、探索、调香台、我的”。
- 第一版使用当前浏览器本地存储，无账号，提供 JSON 导入/导出。两端可访问同一应用，但个人资料不会自动同步。
- 基础香水以数十款真实且有来源的材料为目标，按商家/套件/供应商方案管理；实际数量如实报告。教学概念款仅用于有明确标记的原型测试，不充作正式目录。
- 主流品牌图鉴目标 8–12 个品牌、60–100 个具体产品版本；原料知识目标 20–30 条。数量是交付目标，当前尚未采集完成。
- 配比与画像使用可解释的计算规则，解释文本优先使用模板，不依赖在线大模型。
- 天气、活动先手动输入；自动天气、日历接入和跨设备同步为后续阶段。

首版的验收目标：用户能找到并比较香水，选择多个完整 base 自定义比例，保存和比较作品，记录实际用香，再从已有香水获得有依据的选择建议。

## 3. 主要使用情境

| 情境 | 用户动作 | 应得到的结果 |
|---|---|---|
| 想认识一款香水 | 搜索品牌或产品，打开详情 | 看懂主要香气、版本差异、来源和个人状态 |
| 想理解木质香 | 打开木质标签，再看代表原料 | 知道多个原料能呈现不同木质侧面，不误认某原料一定存在于该香水 |
| 想体验 DIY 调香 | 选择材料体系，浏览完整 base，选择几款，调整比例 | 查看配比、用量及预计画像，保存作品，比较两版差别 |
| 想录入旧配方 | 输入商家、编号和原始 mL 用量 | 原始记录得到保存；身份未知时不产生虚构气味 |
| 准备出门 | 选择活动及天气类别，查看“今日” | 优先从已有香水给出少量建议，并说明个人依据 |
| 用香后想记录 | 选择香水/作品，记下感受 | 快速保存；之后可以补充尾调或他人评价 |

关键路径：探索 → 产品详情 → 加入香水柜 → 今日选择 → 日记；基础香水目录 → 选 base → 调比例 → 解释 → 完成作品 → 版本比较 → 实际感受记录。

## 4. 信息架构与双端布局

| 一级页面 | 主要内容 | 次级页面或面板 |
|---|---|---|
| 今日 | 日期、手动场景、推荐、快速记一条 | 推荐依据、日记编辑 |
| 探索 | 搜索、品牌筛选、香气标签、香水卡片 | 香水详情、两款比较、原料知识 |
| 调香台 | 选 base、编辑比例、预计画像、作品保存 | base 详情、配方版本、两版比较 |
| 我的 | 香水柜、作品、日记、偏好 | 备份恢复、数据管理 |

手机采用底部导航和单列主内容；调香台将“选择基础香水”和“配比编辑”分为可切换面板，合计与保存状态保持可见。桌面使用顶部或侧边导航，调香台可呈现“目录—配比—解释”三列。

移动端用点击、数字输入完成所有操作，不依赖 hover 或拖拽。对比页在手机上按相同字段上下排列，桌面上并排展示。

首屏用香气描述和作品卡引导，化学资料通过“为什么有这种感觉？”展开。CAS、资料版本、算法名称不占主操作区域；需要核对时仍可查看。

布局验收宽度：360、390、768、1440 px。页面无横向溢出；常用触控目标至少 44 × 44 px；键盘可操作输入和导航；焦点清晰；不单靠颜色区分香型或配比状态。字体放大后主要内容仍可读，图表提供文字等价信息。

## 5. 香水图鉴与科学知识

### 5.1 图鉴

- 支持中文名、外文名、别名和品牌搜索；检索与筛选可组合，可一键清除。
- 品牌卡可展示经核验的来源国家/地区作为普通字段；首版不绘制世界地图。地理字段须说明含义，不把品牌起源地当作生产地。
- 产品卡展示真实品牌、完整名称、EDT/EDP 等具体版本、真实图片、主要标签及个人状态。图片需核对具体产品/版本并记录来源和使用条件；缺图条目进入待完善队列，不能以通用图标或生成瓶图充作已完成图鉴。
- 产品详情包含简短描述、官方香调、标签、个人记录、相关风格、来源与核验时间。未知字段明确缺失。
- 同名不同浓度或已确认的不同版本独立建档；不自动视为相同香气。
- 一次比较两款产品，统一字段顺序。品牌未写出的香调显示“资料未列出”，不判定实际不存在。
- 图鉴产品不能因为有香调表就自动成为可混配的 base。

### 5.2 气味词汇与量化

初版教学标尺分两组，属于应用内部表达规则，不声称是唯一科学分类：

| 组别 | 维度 | 说明 |
|---|---|---|
| 香气侧面 | 柑橘、花香、青绿草本、木质、琥珀、麝香、辛香、美食香 | 用于概括气味的不同侧面，可以同时出现 |
| 感受侧面 | 甜感、粉感、清新感、温暖感 | 独立于上组；“美食香”不自动等于高甜度 |

统一 0–5 级：0 表示该套标注中明确没有该侧面，1 弱、2 较弱、3 中等、4 明显、5 强；未知为 `null`，不填 0。分数是感官/教学标注，不是成分百分比。不同维度不相加凑 100%。

每组数值绑定标尺版本、评分方式及来源。原型测试中的概念 base 明确标记，不进入正式材料目录。真实材料只有文本资料时保留标签，不强行转成精确评分；任何编辑推测与实测数值分开展示。

### 5.3 化学解释

原料卡记录名称、原料类型、适用的 CAS/分子结构、气味侧面及有来源的理化数据。物性值同时记录单位、测试条件和来源；未知条件不补造。

原料类型区分单体、异构体/商品混合物、天然复合原料和复合香基。知识关系至少区分：

1. **代表这种气味的原料**：用于科普，没有声称在某款产品中。
2. **来源明确披露的成分**：绑定具体产品与证据，仍不推断含量。
3. **个人感受**：某人在某次使用中报告的气味，不推出化学组成。

点击木质标签，可以查看 Iso E Super® 等代表原料及资料链接，但不能自动显示成“这瓶香水含有 Iso E Super®”。科学参考和边界沿用大纲中的原始来源。

## 6. 基础香水目录

### 6.1 base 的定义

一个 base 是可独立描述的复合基础香水，具有自己的香气主题与组成层次描述。目录可出现类似“雪松与白茶”“玫瑰与柔和木质”的完整主题；这里的名称仅为命名示例，不能视为已存在的商家产品或已验证配方。

每张卡展示：名称、简介、主要气味标签、开场/过渡/尾韵描述（有资料时）、来源类型、可用于模拟的状态。原料或分子解释放在详情，不将代表分子列表冒充实际配方。

### 6.2 三种来源类型

| 类型 | 资料要求 | 可做的事情 |
|---|---|---|
| 教学概念 base | 编辑设计的完整主题、统一标尺画像、版本和设计说明 | 虚拟配比、教学画像、风格关联；不宣称有可直接调出的实体配方 |
| 已核验实体 base | 商家/产品身份、规格与版本、实际来源；评分条件另行注明 | 保存真实配比；满足同标尺条件时进行教学计算 |
| 用户原始 base 记录 | 用户提供的名称/编号和来源备注，可能身份未明 | 保存实际配方和用量；资料不足时不生成画像 |

正式目录以数十款真实、可追溯的 base 为目标，按商家/材料体系管理并如实报告核验数量；不得用概念卡或仅改名称的重复卡凑数。不同目录的编号不通用，不把任何一家店的历史编号总数当作已采集目录。

教学概念款只用于原型测试，卡片和结果均需标记，不算正式内容。对真实 base 同时记录 `浓缩 / 已稀释 / 未知` 状态、载体、质量或体积口径、已知浓度及其定义、适用混配流程。缺少这些信息时不产生确定的稀释建议。

## 7. 调香台交互与计算

### 7.1 配比编辑

主流程默认选择 3 款 base，可增加至 4 款；商家明确指导 2 或 3 款时沿用其规则。1 款用于单独预览或记录；同一 base 版本不重复添加。记录所属目录和流程，不在缺少兼容信息时自动指导跨商家实体混配。

- 首款默认 100%，新增款默认 0%，不静默改变已输入的比例。
- 每项为 0–100%，支持滑杆与数字输入，精度 0.1%。超过精度、负数、非数字显示字段错误，不自动截断成其他数值。
- 界面显示合计和还差/超出多少。计算时使用整数“0.1 个百分点”为单位，避免浮点误差。
- 0% 项可以留在编辑器中，但不参与画像与可计算性判断。
- 合计不为 100% 时允许保存草稿；隐藏当次画像和匹配，不沿用上一次有效结果。
- 合计为 100% 且至少一项为正时，可完成并保存作品。资料不足不妨碍配方记录保存，但相关预测显示“资料不足”。
- 删除有比例的 base 后保留其他数值，提示重新分配；不自动替用户改变其他比例。
- 提供主动点击的“按当前比例凑满 100%”。展示调整结果，用户可应用或取消；全零时不可使用。舍入后确保合计 100%，同余数按选中顺序分配，例如 1:1:1 转为 33.4/33.3/33.3。

百分比表示所选 base 之间的配比，并明确属于质量还是体积口径，不等同于纯香料/分子浓度。流程为“选材料体系 → 选 3–4 款或商家支持的数量 → 小样与调比例 → 确定成品量及计量口径 → 生成用量清单 → 复评留档”。

增加目标成品量（如 30/50/100 mL，重量方案使用 g）、小样量、香精添加比例及其定义、必要的物料规格和对应载体。已稀释基础香水走直接混配路线，不默认增加酒精；浓缩路线按明确方案换算。未知规格只保存比例与原始用量，不猜测稀释量。100 mL 不固定为 20 mL 香料加 80 mL 酒精，g 与 mL 不互换，具体演示见补充确认文档。配方算术不构成实体适用性或安全认证。

### 7.2 旧配方录入

提供“记录已有配方”入口，输入商家、名称、原始 base 编号及 mL 用量。只在单位统一且数值有效时计算相对比例；保留原始用量，不覆盖为百分比。

日本配方验收样例：4.6、3.3、2.1 mL → 合计 10.0 mL → 46%、33%、21%。成品卡的 50 mL、EDP 分别存为原始备注字段，不自动计算或标注“20% 纯香精”。未知 base 保持原始记录类型，不能仅靠编号生成分子组成。

该真实样例只用于私人的录入/测试，不默认预置到公开 H5 的演示目录或任意访客的个人空间。

### 7.3 教学画像

对于有效配比且配比口径与画像模型约定一致，某一维度的教学值：

`作品该轴值 = Σ（base 在模型约定口径下的比例 × base 该轴教学值）`

首批教学模型约定体积比例；质量方案没有适用密度及换算依据时，仅记录用量和定性资料，不直接套用体积模型。

只有所有正比例 base 在该轴都有相同标尺与兼容评分方法的数据时才计算，否则该轴返回未知。不得把缺失当 0，也不得只对已知部分重新归一化。不同标尺或未统一条件的评分不混算。

这是教学线性近似，不声称解决真实混香的非线性。常规结果采用条形及“较弱/中等/明显”等表达，展开时可查看一位小数、计算依据和资料类型。比例的数值精度不代表预测准确率。

配方保存时固定 base 版本、画像输入快照、标尺版本和模拟规则版本；之后目录更新不改写旧作品。需要采用新资料时创建新版本。

### 7.4 输出与相近风格

有效配比的结果面板包括：

1. 预计气味侧面和资料不足的维度。
2. 相比已选旧版本变化最大的两项，解释来自哪款 base 的比例变化。
3. 根据明确气味标签找到的相关品牌香水。
4. 适合哪些气味偏好，以及可尝试的场景；没有个人证据时标为风格建议。
5. 对已实际拥有的实体香水提供“记录实际感受”；纯虚拟作品提供“记下创作想法”，不直接当作已经穿用的香水。

首版风格关联使用可解释标签匹配，不为所有品牌人工补造完整数值向量。作品选取教学值至少为 2 的最多三个主要香气侧面；阈值仅用于筛选展示。遇同分按固定词表顺序，不每次随机变化。

产品标签来自可追溯的香调映射。候选至少与作品有一个主要标签相同，按共有标签数量排序，同分按稳定产品 ID 排序，展示最多三款。结果写明“共同标签：木质、花香”；同时说明品牌另外披露的气味。未披露某标签不能作为实际不存在的证据。

若画像不完整，保留已可计算维度，但不生成整款作品的排名推荐；用户仍可手动点击明确标签探索。没有符合条件的候选时显示无匹配，不编造商品或配比。

两版作品的某轴变化达到 0.2 时可用模板解释变化方向，小于该值写成“教学画像变化较小”。0.2 是可读性规则，不是人类嗅觉阈值。任何描述都不能宣称实际混合后必然如此。

### 7.5 作品与草稿

自动保存可编辑草稿，并提供保存状态。草稿允许合计不为 100%，但各项仍须是合法数值；输入负数、文字或超出精度时保留页面编辑内容，显示当前错误输入尚未保存，不用上次成功状态冒充当前已保存。完成作品时输入名称，创建不可变的版本。修改已完成作品会建立新草稿，完成后产生 v2、v3，不覆盖 v1。

版本对比展示 base、百分比、教学画像与用户补充的实闻感受。日记绑定具体作品版本，后续调配变化不影响旧日记。

浏览器存储不可用或空间不足时显示真实失败，保留当前页面内容并提供导出机会，不显示“已保存”。

## 8. 香水柜、日记与偏好

### 8.1 香水柜

拥有、试过、想试可以分别标记；喜欢、不喜欢是独立偏好，不由拥有状态推导。用户可收藏 DIY 作品版本或手动填写未收录的香水，未收录条目不自动获得科学资料。

明确区分“虚拟作品”和“已实际拥有的实体香水/自制香水”。虚拟作品只能收藏与记录创作想法，不进入今日穿香候选。用户确实调制并拥有某款香水时，另建实体自制香水记录，保存实际材料或原始配方，可关联创作版本；不能把概念 base 自动改写成真实原料。只有实体记录可进入用香日记及穿香推荐。

初始香水柜为空，不从聊天自动公开导入。用户选择录入或导入后，才建立个人档案。

### 8.2 用香日记

记录类型区分“使用香水”和“今天不用香水”。使用香水时，必填仅为实体香水/自制香水与使用时间，时间默认当前本地时间；感受支持一键标签或文字，也可以稍后补记。可选字段包括评分 1–5、用量、场景、天气类别、喷洒位置、开场/后续感受和他人评价。不用香水的记录允许香水引用为空，不提供香水评分，也不参与产品偏好计算。

- 同一天可多次记录，按实际时间排序；区分使用时间和后续补记时间。
- 本人感受与他人评价分开保存；他人可用“同行者”等匿名标识，不必输入真实身份。
- 支持从今日推荐、香水详情、作品详情发起记录，避免重复选择。
- 记录后可编辑或删除，删除需有明确的取消机会。
- 删除个人收藏不连带删除日记；日记保留名称和版本快照。
- 当天不用香水可保存简短记录，不作为负面偏好。

### 8.3 偏好

用户可明确选喜欢/不喜欢的气味标签和排除的具体香水。系统不把一次“太甜”的描述直接写成永久排斥，也不将家人评价并入本人偏好。

修改明确偏好立即影响后续推荐，不改写旧日记或此前推荐记录。性别、职业、人格标签不作为首版评分依据。

## 9. 今日推荐

### 9.1 输入与默认行为

- 候选默认来自已有的实体香水及已实际拥有的自制香水；纯虚拟作品不进入穿香推荐。
- 用户手选活动：如日常通勤、近距离交流、户外活动、休闲独处；可补充自己的备注。
- 天气首版为手动的偏热/适中/偏冷及可选湿度感受；未填就是未知，不能自动假装读取了实时天气。
- 场景标签支持修改，界面不要求填写完整日程。

### 9.2 首版排序规则

先排除用户明确屏蔽的产品。对其余候选，采用简单可审查的规则草案：

`内部排序分 = 2 × 喜欢标签命中数 − 2 × 不喜欢标签命中数 + 场景历史反馈值`

场景历史反馈值取本人对该产品在相同活动和已填天气类别下的历史评分均值，映射为 `(均分 − 3) / 2`，范围 −1 至 1。没有同天气记录时可以退回相同活动，必须在理由中说明；没有相关记录则该项不贡献分数。未评分记录不推断星级，他人评价不参与。

这些权重属于产品排序初值，不是科学或临床结论。缺少产品标签时不凭空补全，匹配项不贡献分数，并注明依据不足。并列时按稳定条目 ID 排序。

展示最多三项且有正向依据的候选；理由必须能追溯到具体偏好或记录，例如“与你明确喜欢的木质标签相符”“你上次在相同活动中给它 4 分”。不能由一次记录写成“你一直喜欢”。

没有历史天气记录时，天气不产生未经验证的效果推断，说明本次主要依据偏好。通用场景文案可以帮助理解，但不冒充个人学习结果。

### 9.3 空状态

- 没有香水柜：引导添加已有香水，仍可浏览图鉴和记录未收录产品。
- 有香水柜但没有偏好或评分：展示“从香水柜选一款”，允许补充偏好；不称为已经个性化的推荐。
- 候选没有正向依据或被排除：说明暂无符合当前偏好的推荐，保留手动选择和今天不用香水入口。
- 未填天气：正常使用其他信息，不编造天气。

推荐选中后仅创建可编辑日记，不直接标记“已使用”。实际用香由用户保存确认。

## 10. 数据与持久化

### 10.1 主要对象

| 对象 | 必要内容 |
|---|---|
| Brand | ID、名称、别名、可核验的地理属性及其含义、来源 |
| Perfume | 品牌、具体版本、名称、真实图片及图片来源/许可/署名、官方香调、映射标签、资料来源、核验时间；未知字段为空 |
| BaseVersion | 稳定 ID、商家/材料目录、版本、物料形态、载体、浓度及其定义/单位、来源类型、复合香气描述、标签、评分/未知值、标尺、评分方法与证据 |
| MixingProtocol | 目录/供应商、支持的 base 与数量、用途、直接混配或浓缩稀释路线、计量口径、适用添加量和制备步骤的来源 |
| Material | 类型、名称、适用的化学标识、气味侧面；物性值的单位、条件与来源 |
| Evidence | 来源类型、标题/URL、核验日期、适用对象与字段、复用状态 |
| BlendDraft / BlendVersion | 方案、配比及质量/体积口径、目标成品量、小样量、香精添加比例及定义、base 规格快照、原始用量、规则版本、名称、创建时间；草稿可不完整 |
| CollectionEntry | 产品/实体自制香水/虚拟作品/手动条目、实体或虚拟身份、拥有/试过/想试状态、名称快照；实体自制香水可关联创作版本 |
| WearLog | 类型 `wear / no_fragrance`、使用时间、实体香水引用及配方版本快照、本人评分与描述、场景天气、他人反馈、补记时间；不用香水时引用可为空 |
| Preferences | 用户明确的喜欢/不喜欢标签、屏蔽产品、更新时间 |
| BackupEnvelope | 备份格式版本、导出时间、个人数据及必要引用快照 |

base 百分比保存为整数单位，1000 代表 100%；评分未知值为 `null`。商家原始体积记录保存数值和单位，不能拿百分比字段替代。时间保存可还原的时间点与时区信息，日记按用户本地日期显示。

### 10.2 本地保存与双端关系

公共目录与私人数据分开。首版采用静态公共目录与浏览器本地数据库的前端架构即可；具体框架和依赖在构建时选择，无需先建设账号或服务器业务系统。

首版私人配方、日记、偏好和导入文件不发送至服务器、统计服务或在线模型，也不放入页面 URL。加载公共资源可以联网，涉及个人内容的操作保持在浏览器内。

同一个 H5 地址可在手机、电脑打开，但每个浏览器/站点来源维护自己的私人数据。更换浏览器、设备或站点来源不会自动迁移；清除站点数据可能丢失本地记录。相关说明放在备份设置，不干扰每次用香。

### 10.3 导入导出

导出包含香水柜、偏好、草稿、作品版本、日记及恢复所需的引用快照，不只导出目录 ID。备份格式有明确版本。

首版导入只支持“替换当前个人资料”，不实现隐含的自动合并。先检查文件结构、版本、比例和值域以及引用完整性；完成作品必须合计 100%，草稿允许合法数值合计不足或超出 100%，不能因此拒绝有效备份。非法数值与格式错误仍应拒绝。检查通过后显示条目数量和替换说明，提供导出当前资料的入口；用户明确确认后原子替换。取消、格式错误或不支持的版本均不改变原数据。

缺少公共目录中的旧对象时，使用备份内的快照保持历史记录可读，不能静默丢弃日记。私人备份不需要上传服务器，也不包含公共数据库的批量再分发功能。

支持删除单条个人内容和清空个人数据；清空有明确确认并保留备份入口，不删除公共目录。

## 11. 内容准备与发布门槛

| 内容 | 完成标准 |
|---|---|
| 品牌图鉴 | 每个真实产品身份和公开香调有来源；真实图片与具体版本匹配；未知值保留；图片署名和素材复用状态清楚 |
| 正式 base 目录 | 采用真实材料而非教学概念卡；商家/体系与版本清楚；实际数量如实报告；物料形态及流程信息可追溯 |
| 实体 base | 提供商家、编号/名称、规格和版本证据；文本与数值数据分别注明方法；不够则仅记录 |
| 原料知识 | 原料类型准确；物性有单位/条件；代表原料与已确认成分关系不混同 |
| 个人数据 | 演示内容使用虚构示例，不含用户私人真实配方、日记或家人反馈 |
| 算法解释 | 任一数值能追溯到输入和版本；无数据时不填补；不显示未验证准确率 |

原型阶段可使用少量清楚标记的内容样本测试流程；完整首版发布前需满足目标目录规模或明确报告实际规模。不能把占位卡、重复卡计入已完成目录。

具体数据来源、授权条件与科学参考见大纲、补充确认及各条目的 Evidence。供应商建议用量不转写成安全上限。实体用量清单仅在规格和方案具备时计算，不宣称自动通过完整适用性或安全评估。

## 13. 交付顺序

1. **需求基线**：本 PRD 与大纲 v0.2；确认已纳入用户对完整 base、自由配比和 H5 的要求。
2. **交互与视觉原型**：以探索、调香台、今日记录验证信息层次及移动端操作；确定视觉方向后实施界面。
3. **基础功能构建**：先做公共目录、base 选择与比例、作品版本、本地保存；再接日记、偏好和解释性推荐。
4. **内容与整体验收**：逐条核验数据来源，执行上表主要用例，分别报告浏览器验证、数据覆盖和未验证能力。
5. **后续增强**：基于真实使用反馈决定自动天气、日历、同步和实闻校准优先级。

无需等待参考地图链接即可开始原型。数据规模、本地保存和排序权重仍是可调整的实现建议；真实图鉴、以 3–4 款为主且服从商家规则的调香流程、H5 和多商家形式按用户最新确认执行。
