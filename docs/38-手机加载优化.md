# 手机加载优化

日期：2026-11-09。针对 GitHub Pages 手机上首次打开较慢的问题。

## 调整

- 调香首屏不再静态导入、转换和索引全部 26,335 条档案；进入图鉴、今日或“我的”时才请求图鉴。加载期间可返回调香，过期的导航不会覆盖当前页面；失败提供重试入口。
- 保留已有香柜 ID，不能因图鉴尚未加载而清空个人记录。
- 线上构建使用 esbuild 合并、压缩和拆分脚本；脚本和样式使用内容哈希文件名，避免新入口复用旧代码。四份样式合并为一份。
- 仅构建产物省去界面未使用的英文原始介绍；完整原文、来源和图片仍在源仓库。新增测试逐条确认除原始英文 description 外，其余字段完全一致，包括中文介绍、前中后调、版本、场景与图片路径。
- 星图只加载聚类数据、局部分组与渲染器；品牌地图再请求世界底图、行政区和真实品牌位置。成功下载的资源复用，失败的资源可以重试。

## 体积对比

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首屏必需 JS / 数据源码 | 13.77 MB | 387,498 B |
| 首屏 JS 离线 gzip 估算 | 5.05 MB | 114,699 B |
| 首屏脚本模块数 | 45 个生产源模块（部分 URL 重复） | 2 个构建模块 |
| 按需图鉴模块 | 与首屏一起加载 | 8,177,517 B，离线 gzip 2,651,241 B |
| 星图附带世界及行政区底图 | 约 5.08 MB | 不加载，进入地图再请求 |

上述是构建字节与 gzip 估算，不是手机 4G 实测秒数；图片仍按页面懒加载，未删减或重新压缩。

## 验证

- 85 项测试通过：原 82 项，以及分视图资源请求、失败重试、全库展示字段一致性。
- 生产构建在 390 × 844 浏览器视口检查图鉴、香水详情、星图→地图→星图、今日推荐及已有香柜信息；控制台无 error。
- 本地 HTTP 请求日志确认首屏无图鉴数据请求；进入图鉴才请求 data 分包；星图不请求 world/admin1/brand-locations。
- GitHub Pages 原始站点实查使用 gzip，原 catalog-full-rows.js 传输 Content-Length 为 4,652,028 B。
- 未测用户物理手机、移动运营商网络或端到端 LCP；访问 GitHub Pages 的网络延迟仍可能影响体感。
